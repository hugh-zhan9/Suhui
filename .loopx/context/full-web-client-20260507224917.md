# Context Snapshot: Full Web Client

## Task Statement

Plan a complete browser-accessible Web endpoint for Suhui that is hosted by the running Desktop app and backed by Electron main application services.

## Desired Outcome

The Web endpoint is a formal client over `IP + port`, not a lightweight reader shell. It uses Electron main as the authoritative service host and local Postgres as the single source of truth.

## Known Facts / Evidence

- `AI-CONTEXT.md` states the repository is desktop-only and `apps/ssr` / `apps/mobile` were removed.
- `AI-CONTEXT.md` states current remote access is Electron main HTTP server + renderer `remote.html`, with partial reading and light subscription management only.
- `apps/desktop/layer/main/src/remote/manager.ts` currently exposes `/health`, `/status`, `/events`, `/api/subscriptions`, `/api/entries`, `/api/unread`, `/api/entries/read`, and refresh endpoints.
- `apps/desktop/layer/main/src/application` currently has early service files for entry, feed, subscription, and unread.
- `SubscriptionApplicationService.createSubscription()` currently calls back into `DbService.addFeed`, which means service extraction is incomplete.
- `apps/desktop/layer/main/src/ipc/services/db.ts` owns RSS preview/add/refresh/batch refresh/delete-subscription behavior and should be a major extraction source.
- `apps/desktop/layer/main/src/ipc/services/setting.ts` owns appearance and RSSHub custom URL, but also has non-goal desktop-specific methods like login item, tray, system fonts, proxy, notifications.
- `apps/desktop/layer/main/src/ipc/services/sync.ts` owns sync status and snapshot import/export-style operations.
- `apps/desktop/layer/main/src/ipc/services/app.ts` owns `exportEntryAsPDF()` and many desktop-only utilities.
- `packages/internal/store/src/remote/*` currently provides remote hydrate/SSE helpers with direct `/api/*` fetch calls.
- `packages/internal/store/src/modules/*/store.ts` still branches directly on `getRuntimeEnv()`, `window.electron`, IPC, and `/api/*`.
- `apps/desktop/layer/renderer/src/remote/remote-app.tsx` is a lightweight standalone remote UI, not the full desktop main UI.

## Constraints

- Do not create an independent `apps/server` product.
- Do not replace local Postgres as the single source of truth.
- Do not add authentication, access codes, permissions, or read-only mode in first version.
- Do not delete the old remote entry without explicit user approval.
- Preserve desktop local RSS stability.

## First-Version Scope

- Reading
- Subscription create/update/delete
- Batch subscription management
- Refresh
- Unread/read state
- Settings pages
- Import/export
- RSSHub configuration
- PDF export

## Non-Goals

- Window controls
- Tray behavior
- Open-at-login controls
- System font enumeration
- Dock badge
- System notifications
- Eagle integration
- Obsidian integration
- qBittorrent integration
- Native folder picker
- System-level proxy switching

## Decision Boundaries

Agent may decide:

- Application service split and naming
- IPC/HTTP adapter interface shape
- Web runtime adapter module boundaries
- Remote UI retain/replace/migrate strategy
- Test layering
- Migration order

Agent must ask before:

- Changing no-auth model
- Adding first-version scope
- Introducing a new top-level app/package
- Changing Postgres source of truth
- Deleting old remote entry
- Large-scale removing existing modules

## Unknowns / Open Questions

No blocking clarify questions remain. Planning should preserve residual risks rather than reopen scope.
