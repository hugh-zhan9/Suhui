# 本地阅读工作流增强：澄清记录

## 来源

- 用户要求新增：真正可恢复的备份与 OPML、内容去重聚类、规则引擎、本地笔记与高亮、阅读队列。
- 项目定位以 `AI-CONTEXT.md` 为准：Desktop 主端、PostgreSQL 本地数据面、Remote 为 Desktop 托管入口。

## 已确认决策

1. 内容去重采用“聚类但不删除”。列表可折叠为代表条目，用户可展开全部来源；逐篇已读、收藏、队列、笔记和高亮状态保持独立。
2. 备份恢复提供两种模式：默认合并；完整替换前自动创建安全快照并二次确认，失败自动回滚。
3. 规则默认只作用于启用后新抓取的文章。历史执行必须先预览命中数量再确认；隐藏只影响普通列表，不删除数据，搜索和规则管理仍可访问。
4. 稍后读与已读、收藏完全独立。只有显式“完成”才退出待阅读队列，完成记录用于积压量与阅读进度统计。
5. 笔记绑定具体条目。高亮保存原文、上下文和正文类型；正文变化后尝试重新定位，无法可靠定位时保留为失效高亮，不静默删除或错误迁移。
6. 重复文章之间不自动共享笔记、高亮或其他逐篇状态。
7. 规则中的“分类”采用文章级本地标签，不修改订阅分类。标签可手动增删、用于筛选/搜索/备份，且不跨重复聚类继承。
8. 聚类代表文章按稳定顺序选择：用户手动指定优先；否则有稍后读/加星/笔记/高亮等用户投入的版本优先；否则正文更完整的版本优先；最后按发布时间最早选择。用户手动选择持续保留。

## 边界

- 不删除聚类中的重复条目。
- 不让规则编辑静默改写历史文章。
- 不把“已读”解释为“完成稍后读”。
- 不把 OPML 当作完整备份；OPML 只迁移订阅与分类。
- 不依赖云端服务完成上述能力。

## 仓库证据

- 当前 JSON 导出仅覆盖 feeds、subscriptions、collections、readEntries：`apps/desktop/layer/main/src/application/import-export/service.ts`。
- 当前 Desktop OPML 导入/导出仍调用在线 Folo API：`DiscoverImport.tsx`、`OpmlSelectionModal.tsx`、`data-control.tsx`。
- 主数据面为 PostgreSQL，schema 位于 `packages/internal/database/src/schemas/postgres.ts`。
