# 溯洄后续迭代方向

> 状态：现行方向
> 记录日期：2026-08-12
> 产品锚点：完全本地 RSS 阅读器（Desktop 主端）+ 运行中 Desktop 托管的 LAN / VPN 远程阅读入口
> 不追求：会员/计费、登录强依赖、在线 AI 主链路、Redis / 换库换栈换性能

本文档是性能重构完成后的产品迭代方向。实现细节仍以代码与 [AI-CONTEXT.md](../AI-CONTEXT.md) 为准；若本文与历史设计/计划冲突，以本文与 `AI-CONTEXT.md` 为准。

## 产品判断

溯洄应强化「可信的本地资料库 + 顺手的跨设备阅读」，而不是长成云端信息流产品。

性能主因已通过有界查询、渐进加载、刷新 ChangeSet、Remote shell-first 等路径收敛；后续优先补体验与本地能力完整度，而不是再引入缓存中间件或第二套数据面。

## 近期待办优先级

若同时只能推进少量事项，按此顺序：

1. **本地全文搜索**（标题 + 正文；优先 Postgres FTS）+ **坏源 / 刷新状态可视化**
2. **已交付：OPML / 完整备份一等公民**；完整备份在 Remote 最小鉴权前保持 Desktop-only
3. **本地 readability / 全文缓存** + **远程最小鉴权**（token/密码、只读、绑定网卡等）

## 1. 优先把现有能力做扎实

### 1.1 远程端补齐「日常够用」

远程端已具备阅读、已读/未读、feed 刷新、轻量订阅管理、本地 OPML，以及规则/注释/阅读队列的共享核心操作。仍缺：

- 设置页
- 完整备份导入导出（需先有最小鉴权）
- 批量订阅操作
- 分类级管理

目标：手机或另一台电脑通过 `IP + 端口` 能完成日常阅读与基础订阅维护，而不是半成品只读壳。

### 1.2 订阅与刷新可观测性

仓库已有刷新审计日志基础。产品内应可见：

- 哪些源失败
- 多久未成功更新
- 上次成功时间
- 失败原因归类（超时 / 403 / 解析失败等）

本地阅读器最伤体验的是静默坏源。

### 1.3 正文质量与离线可读

- 收敛残留在线 `readability` 等能力为本地下载 / 抽取 / 缓存
- 打开文章的完整度与离线可用性优先于再堆列表特效

### 1.4 残留在线能力收敛

translation / summary / discover 等若仍挂远端：

- 能本地化则本地化
- 否则明确关闭或降级提示

避免「以为本地却偷偷联网」。

## 2. 值得新增、且贴合定位的功能

| 方向           | 说明                                                                |
| -------------- | ------------------------------------------------------------------- |
| 本地全文搜索   | 订阅变多后，搜索比 Discover 更刚需；用现有 Postgres，不另起搜索服务 |
| OPML / 备份    | 导入导出、定期备份、换机恢复；建立本地产品信任感                    |
| 规则与收件箱   | 按源 / 关键词自动已读、加星、进分类；过滤噪声源                     |
| 阅读节奏工具   | 稍后读、加星、本地笔记/高亮、按源阅读进度                           |
| 远程最小安全层 | 在 LAN/VPN 假设下增加 token/密码、只读模式、绑定网卡                |
| 系统级 TTS     | 若要做，优先系统离线方案；不做在线语音主链路                        |

## 3. 明确不优先 / 不押注

- 用 Redis 或换存储「解决性能」——主因已不在缺缓存层
- 会员、登录、在线 AI 作为主阅读链路
- 把 Remote 做成完整第二套 Desktop UI（应共享应用层，只补关键缺口）
- 恢复内嵌 RSSHub 运行时（继续外部实例模式）
- 无测量依据的全仓依赖清理或技术栈重写

## 4. 与当前执行基线的关系

`AI-CONTEXT.md` 中的近期执行优先级仍然成立，并与本文对齐为：

1. 保持完全本地 RSS 可用性稳定
2. 稳定并扩展远程浏览器访问的日常可用性
3. 收敛残留在线能力入口
4. TTS 仅在需要时走系统离线方案
5. 按本文「近期待办优先级」推进搜索、备份、正文本地化与远程安全

历史性能重构文档（`docs/loopx/.../2026-07-13-suhui-performance-refactor/`）视为已完成基线，不再作为未完成需求来源。

## 5. 2026-08-12 已完成基线

- 完整、可校验、可合并/替换恢复的本地备份；replace 带安全快照、二次确认和事务回滚
- 本地 OPML 预览、选择性导入与导出
- 不删除原文的转载/重复条目聚类与人工代表项
- 新文章规则、历史预览确认、文章标签和隐藏
- 逐篇本地笔记、高亮重定位与搜索
- 与已读、收藏独立的稍后读队列、积压量和完成统计

完整备份包含私密阅读数据，因此 Remote 在最小鉴权落地前不提供备份下载或恢复；Remote OPML 不包含正文和阅读状态，可继续使用。
