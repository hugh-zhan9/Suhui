## D-004 · Interface / Data Contract

新增 Desktop IPC `db.loadFeedHistory(feedId: string)`，只接受有效订阅 ID，不接受任意网页 URL 或调用方提供的游标。返回 `{ added: number, hasMore: boolean, status: "more" | "complete" | "unsupported" | "limit", scannedPages: number }`；异常沿现有 IPC Error 传播，renderer 在列表末尾显示可读说明和可复制原因，允许手动重试。

进程内每个 feed 保存站点地址、待扫描页、已扫描 URL、可信列表结构、未处理文章和完成状态；同一 feed 的在途请求复用同一 Promise。数据库对象或订阅源地址变化后废弃进度。不在 main 中保存 renderer 导航状态；切换订阅不再发起旧订阅新批次，已经开始的一批可完成入库。

renderer 仅在 Desktop 的单订阅 Articles 列表末尾触发，先耗尽本地分页；用户发生向下滚动交互后才开始历史请求，短列表允许滚轮触发。初次打开页面不自动抓完整站点。完成后沿用文章查询重新取数，但此轮不执行列表回顶。新增条目按既有排序、过滤和规则呈现。失败及 unsupported/limit/complete 不继续自动请求。

<a id="D-005"></a>

## D-005 · Security / Operational Contract

归属 `application/feed` 的网页读取器仅访问 http/https 公网站点；所有索引页、正文和每次重定向必须与初始站点同 origin，无 userinfo。DNS 解析结果必须为公网地址，并将已校验结果绑定到实际连接，防止校验与连接之间再次解析。不得继承浏览器 Cookie、认证头或自动执行网页脚本。最多 3 次同源跳转，每请求总时限 15 秒、正文上限 2 MiB；不自动重试或跨源降级。远端广告/正文链接、localhost、私网、IPv4-mapped IPv6、环路跳转均不能扩大抓取范围。

列表识别复用 `site-scrape` 的导航过滤、可靠日期及置信度约束，扩展 `.post-item` 容器及完整标题读取。历史模式可合并多个通过阈值的组；单篇/双篇尾页仅允许已确认结构继续，不降低普通新增订阅的门槛。只从页面实际出现的下一页/归档链接继续；归档目录本身不入库为文章。

正文由已取回的 HTML 交给 Readability，不允许正文提取再自行联网；相对媒体/链接以文章实际地址归一，移除脚本、嵌入式执行元素与事件属性，继续经过既有 renderer 正文处理。不把解析失败的导航页或摘要伪装成完整正文。

<a id="D-006"></a>

## D-006 · Data / Concurrency Contract

沿用 entries 表，无迁移。URL 归一仅去 fragment、整理末尾斜杠，保留有业务意义的 query。补全前读取同 feed 的全部已存 URL（含软删除，避免复活）；网络完成后在同 feed 的串行写入段再次读取。已存在行不更新，新行采用稳定 URL 身份、正文、真实发布时间和 `read=false`，冲突 `DO NOTHING`。不重写既有 ID、正文、已读及附属表。历史 ID 带 `local_history_` 前缀；后续 RSS 刷新仅对此类候选增加 URL 匹配，从而复用历史 ID，不扩大普通 RSS 不同 GUID 条目的合并规则。

两个既有刷新实现 `ipc/services/db.ts` 和 `manager/feed-refresh.ts` 与历史提交使用同一个 feed 写入协调器。普通已读/笔记/收藏操作无需加入协调器，因为历史分支只插入新行。历史批次在 DB 维护跟踪中运行；入库前重读订阅是否有效，退订不被恢复。原 RSS 刷新仍固定 `allowDiscovery:false`，补全失败不写 feed.error，也不把抓取地址替换为订阅地址。

新文章继续经过已有 `localReadingPipeline`；查询失效及未读刷新沿用 renderer 能力，不新增 Remote HTTP 路由。前一批的已提交文章不因后一批失败回滚；未提交批次失败不推进扫描进度，显式重试同批次。

## Verification Strategy 与执行边界

- 列表解析：真实 Lynan 卡片最小结构、同源分页/归档、导航排除、已知结构单篇尾页。
- 网络：mock request/DNS 校验、实际连接绑定、逐跳同源、响应大小、超时、错误停止；真实站点只读抓取验收。
- 数据：10 篇已存与 66 篇网站的合并、重复 URL、软删除、未读保留、刷新复用、批次失败、并发同 feed，SQLite 实库执行及 Postgres SQL 合同。
- renderer：未滚动不触发、本地未耗尽不触发、滚动到底自动触发、请求中不重复、错误停止、切换订阅、补全重查不回顶。
- 运行已有受影响测试、格式/lint、渲染层类型检查与 Electron 构建。主进程全量 tsc 已知存在 rootDir/include 配置错误，单独记录，不借机修改。
- 代码完成后按仓库要求对新增网页请求边界及准确 diff 做独立安全评审；修复重要发现后重新验证和复审。

### 补全后日期排序回归

用户随后反馈原 RSS 文章不见：数据库中 64 篇均在，原 RSS 的 10 篇发布时间为 0，因而排在历史文章之后。实际源日期采用 `7 月 15 日，2026` 格式；解析器现支持该完整格式，按 UTC 零点归一并拒绝日历溢出。更新后正常刷新沿原 GUID/ID 修正日期，无需重建订阅。真实源 10 个日期全部解析成功；内存数据库模拟确认 64 篇记录及已读状态保留、10 篇恢复排序。新增日期回归及独立兼容性复审通过；最终 main 全量 638 通过、12 跳过，Electron 构建通过，旧文件既有 lint 错误未扩大修复。
