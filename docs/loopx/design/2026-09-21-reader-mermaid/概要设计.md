# 阅读模式诊断与 Mermaid 图表

2026-09-21。来源：用户确认补上阅读失败日志和 Mermaid 渲染；问题文章为 `local_entry_local_feed_1789976028016_kqudaem_5649da1dd506f53f`。功能范围已批准，以下为范围内的实现选择；未授权安装或部署。

## 本地渲染边界

复用 renderer 的 `lib/parse-html.ts` 中 `pre` 扩展点及现有 HTML 清洗。文章的 RSS 正文与 readability 正文走同一路径。仓库没有 Mermaid 实现，新增固定版本的本地依赖，按需加载。

文章 HTML → 现有清洗 → `pre.mermaid` / `pre.language-mermaid` / `pre > code.language-mermaid` → 本地 Mermaid → 静态 SVG 图片。

<a id="D-001"></a>
**D-001 · Behavior / Security Contract · 范围内实施裁定**：普通代码块和正文清洗不变，仅保留 Mermaid 所需的 pre class 标记。图表在 renderer 本地生成，使用 strict 安全级别、锁定站点配置、不绑定图表点击回调，以图片上下文隔离输出 SVG。明暗主题变化重新生成；并发生成串行处理 Mermaid 全局配置，切换文章或卸载忽略迟到结果，临时布局节点始终清理。图表失败显示错误并保留可查看源码，失败不影响正文。沿用 Mermaid 的 50,000 字符及 500 边限制。不运行原站脚本、不增加远端绘图服务、不改写数据库中的原文。

## 诊断边界

<a id="D-002"></a>
**D-002 · Operational Contract · 范围内实施裁定**：在现有 readability 包增加可选诊断回调，未传入时保持原行为。由主进程 reader IPC 写入既有轮转 `main.log`，记录诊断 ID、文章 ID、阶段、耗时、HTTP 状态、错误类别及 cause 链网络错误码。URL、凭据、正文和原始异常消息不写日志。诊断回调失败不得改变读取结果；不增加重试或改变超时。renderer 捕获失败时记录对应诊断信息并显示可复制提示。已有空结果行为保留。

## 验证

使用报告文章的实际图表源码验证图形；覆盖 HTML 两种格式、普通代码块、空/超限/非法源码、暗色、多个图表、失败后继续渲染、卸载与迟到结果、安全配置覆盖和脚本注入。日志覆盖成功、请求失败、响应体失败、解析失败及日志写入失败，断言无正文和 URL 泄漏。运行相关单测、类型检查和 Desktop 构建；最终 diff 进行独立安全审查。

设计走查：正常文章仅在展示层产生图片，缓存正文保留源码；抓取失败仍由原调用方处理，图表解析失败局限在当前块。没有新服务、数据库结构或持久化状态。Support lenses: none。

### 审查修正

独立审查发现 Mermaid 的图片节点会等待网络图片，可能堵住全局绘图队列。实现已在布局前检查解析后的节点数据（支持带引号的属性键），拒绝图片节点，不发起该网络请求；其他图表继续绘制。`noMedia` 预览去掉图表渲染标记并保留代码正文。生成图片使用 SVG viewBox 的固有尺寸，避免浏览器默认 300×150 尺寸导致错误缩放。

IPC 框架会打印所抛 Error 的 cause，因此主进程提取安全字段后只抛新诊断异常，不附带原始 cause。
